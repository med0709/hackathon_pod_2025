📘 Documentação da Arquitetura de Dados

1. Visão Geral da Arquitetura

A arquitetura proposta segue o padrão de Data Lake em camadas, implantado em uma OCI Region, com o objetivo de suportar análises de dados, modelos de ciência de dados e governança de informações provenientes de múltiplas fontes.

O fluxo de dados foi desenhado para garantir:

  • Escalabilidade
  • Qualidade dos dados
  • Rastreabilidade
  • Segurança
  • Separação clara de responsabilidades

2. Fontes de Dados

As fontes representam sistemas externos responsáveis pela geração dos dados brutos, como:

  • Sistemas corporativos (ex: operadora, CRM, billing)
  • Bases transacionais
  • Arquivos estruturados ou semiestruturados
  • Integrações via API ou batch

Esses dados são ingeridos sem transformações iniciais, preservando o estado original para auditoria e reprocessamento.

3. Camadas do Data Lake

🟦 RAW Camada Bruta

Objetivo: Armazenar os dados exatamente como foram recebidos da fonte.

  • Dados no formato original
  • Sem tratamento ou padronização
  • Pode conter erros, duplicidades e valores nulos
  • Usada para auditoria e reprocessamento

Boas práticas:

  • Particionamento por data de ingestão
  • Versionamento dos arquivos
  • Escrita append-only

🟨 TRUSTED Camada Confiável

Objetivo: Realizar limpeza, padronização e validações básicas de qualidade.

  • Conversão de tipos (datas, numéricos, strings)
  • Padronização de formatos
  • Remoção de duplicidades
  • Tratamento de valores nulos
  • Criação de colunas técnicas (ex: SAFRA)

Resultado: Dados confiáveis para consumo analítico, mantendo rastreabilidade com a RAW.

🟩 REFINED Camada Analítica

Objetivo: Disponibilizar dados prontos para análise e modelagem.

  • Dados agregados e enriquecidos
  • Regras de negócio aplicadas
  • Métricas consolidadas (U1M, U3M, U6M, U12M)
  • Estrutura orientada ao consumo

Consumidores:

  • Análise de Dados
  • Ciência de Dados
  • Dashboards
  • Modelos preditivos

🟥 CONTROL Camada de Controle e Qualidade

Objetivo: Garantir governança, monitoramento e qualidade dos dados.

  • Métricas de qualidade (nulos, inválidos, duplicados)
  • Logs de execução
  • Auditoria de volumes
  • Status de pipelines
  • Indicadores de SLA

4. Orquestração e Fluxo de Dados

  • Sequenciamento das camadas (RAW → TRUSTED → REFINED)
  • Reexecuções automáticas
  • Tratamento de falhas
  • Dependências entre processos

Ferramentas típicas:

  • Data Flow
  • Jobs Spark
  • Workflows agendados

5. Serviços de Suporte e Governança

🔐 Key Vault

  • Armazenamento seguro de credenciais
  • Tokens de API
  • Chaves de acesso
  • Segredos sensíveis

👤 IAM (Identity and Access Management)

  • Controle de acesso por usuários e grupos
  • Permissões por camada
  • Princípio do menor privilégio

⚙️ Functions

  • Processamentos event-driven
  • Validações automáticas
  • Envio de alertas
  • Integrações auxiliares

🔔 Notifications

  • Alertas de falha
  • Notificações de sucesso
  • Avisos de quebra de SLA
  • Comunicação com times de dados

6. Consumo de Dados

📊 Análise de Dados

  • Exploração dos dados
  • Geração de insights
  • Relatórios e dashboards
  • Análises descritivas e diagnósticas

🤖 Ciência de Dados

  • Feature engineering
  • Treinamento de modelos
  • Análises preditivas
  • Modelos de churn, risco ou comportamento

Os dados consumidos vêm prioritariamente da camada REFINED, garantindo qualidade e consistência.

7. Benefícios da Arquitetura

  • Separação clara de responsabilidades
  • Alta escalabilidade
  • Governança e auditoria nativas
  • Facilidade para análises e ML
  • Redução de retrabalho
  • Aderência a boas práticas de mercado
